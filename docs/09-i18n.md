# 09 · Internationalisation

> 中文摘要：语言文件为 JSON，键名点分层级；当前支持 zh-CN 与 en，切换无需重启。
> 新增语言只需添加资源文件并注册。

## 1. Supported languages

| Code | File | Status |
|---|---|---|
| `zh-CN` | `src/i18n/locales/zh-CN.json` | complete for 1.0 UI |
| `en` | `src/i18n/locales/en.json` | complete for 1.0 UI |

The default is `zh-CN`; the choice is stored per device in settings and applied
by `i18n.changeLanguage()` without a reload.

## 2. File format

- JSON, UTF-8, no comments.
- Nested keys: `area.element`, e.g. `reports.exported`, `task.priority2`.
- Interpolation uses `{{name}}`; never build sentences by concatenation.
- Plurals use i18next plural keys (`_one`, `_other`) when a language needs them.
- Chinese and English files must have identical key sets. A missing key falls
  back to English, but that is a bug, not a feature.

## 3. Naming conventions

- Areas: `app`, `nav`, `onboarding`, `actions`, `task`, `reports`, `settings`,
  `days`, `common`.
- Actions are verbs (`actions.save`), states are nouns (`task.completed`).
- Do not embed product names or punctuation in keys.

## 4. Dates and numbers

- Dates are formatted with `date-fns` and the matching locale (`en-US`,
  `zh-CN`), never with hand-written month names.
- Week starts on Monday in both languages (project convention).
- Report numbering is independent of language: Chinese numerals are a user
  choice, not a locale rule.
- Use `Intl`/`date-fns` for times; do not assume a 12/24-hour format.

## 5. Adding a language

1. Copy `en.json` to `<code>.json` and translate every value.
2. Import and register it in `src/i18n/index.ts`.
3. Add the option to the Settings language select.
4. Run the key-parity test (planned) and the manual smoke list.

## 6. What is not translated

- User data: task titles, category names created by the user, report filenames.
- Seeded category names are stored in both languages, so they follow the UI
  language without rewriting rows.
- Log messages and developer errors stay in English.
